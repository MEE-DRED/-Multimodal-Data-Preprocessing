## Naming convention and mapping
Canonical names: `member_<N>_<expression>.jpg`, lowercase, underscores, no personal names.
The supplied ZIP used different names; files were mapped (byte-for-byte copies, only renamed) as recorded in `data/processed/original_file_mapping.csv`:

| Supplied path | Canonical path |
|---|---|
| `Member 1/{neutral,smiling,surprised}.jpg` | `member_1/member_1_<expression>.jpg` |
| `Member 2/{...}.jepg` (note: `.jepg` typo in the upload) | `member_2/member_2_<expression>.jpg` |
| `Member 3/{...}.jpeg` | `member_3/member_3_<expression>.jpg` |

The ID↔person mapping is kept by the team outside public filenames (Member N = the Nth team member in the team agreement).

## Folder organisation
```
data/raw/images/member_N/        original images (never modified)
data/processed/                  image_features.csv, processed_image_manifest.csv, augmentation_manifest.csv, original_file_mapping.csv
outputs/augmented_images/member_N/   <stem>_{rotation,flip,grayscale,brightness}.jpg  (long side <= 1024 px)
outputs/processed_images/member_N/   <stem>_face160.jpg  aligned face crops (generated by the notebook)
data/test_unknown/person_N/       UNKNOWN (not enrolled) test images: person_N_{neutral,smiling,surprised}.jpg - never used for enrolment or templates
outputs/unknown_processed_images/person_N/   aligned 160x160 crops of the unknown persons (generated by notebook Section 11)
```

## Image inspection findings
| Member | Format | Dimensions (w×h) | Mode |
|---|---|---|---|
| member_1 | JPEG | 958×933, 959×1031, 865×865 | RGB (3 ch) |
| member_2 | MPO (multi-picture JPEG from a phone camera; Pillow reads it as JPEG) | 3024×4032 (all three), ~2 MB each | RGB (3 ch) |
| member_3 | JPEG | 810×1080 (all three) | RGB (3 ch) |

Observations: resolutions and file sizes differ greatly between members (78 KB – 2 MB). Each member was photographed with a different background, framing and camera; this is a confound (see `model_card.md`). EXIF orientation of all files is 1 (no rotation needed). Images are down-scaled to ≤ 1024 px long side only inside the pipeline; originals are untouched.

## Augmentation organisation
Four augmentations per original: `rotation` (+8°), `flip` (horizontal), `grayscale`, `brightness` (×1.2). Each output keeps the original stem plus a suffix. `data/processed/augmentation_manifest.csv` lists member, original filename, augmentation type and output filename for all 36 outputs. Augmented files stay in the same data partition as their original in every evaluation.
