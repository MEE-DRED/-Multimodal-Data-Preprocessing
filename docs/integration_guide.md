# Integration guide – calling the face component

```python
from src.face_model import verify_face          # run from the project/repo root
result = verify_face("path/to/submitted_image.jpg")
```
Command line: `python -m src.face_model path/to/image.jpg`

## Return value (always a dict; never raises on ordinary bad input)
| Field | Meaning |
|---|---|
| `verified` | `True` only if the best similarity ≥ threshold (0.70). **This is the authorisation decision.** |
| `user_id` | Matched member (`"member_1"`…) if verified, else `None` |
| `score` | Cosine similarity of the best match (0–1, higher = more similar); `None` if no score could be computed |
| `message` | Human-readable text |
| `status` | `verified`, `below_threshold`, `file_not_found`, `unreadable_image`, `no_face_detected`, `model_unavailable`, `error` |
| `best_match` | Nearest member even when rejected – for debugging only, **never use it for access** |
| `threshold`, `num_faces` | Threshold used; faces detected (largest is used) |

## Required order in the final application
1. Call `verify_face(image_path)`.
2. If `result["verified"]` is `False` → deny the transaction and **stop** (do not request voice, do not show a recommendation).
3. If `True` → run the voice component with the expected speaker `result["user_id"]` (e.g. `verify_voice(audio_path, expected_user_id)`), as in the team agreement.
4. Only when both pass call the product model and show its prediction.

The face module never accepts or processes audio. Team demo scenarios map to: authorised face → `verified=True`; unauthorised face → `verified=False` (add a consented non-member photo to demonstrate).

## Requirements for the integrator
* Files: `src/` (face_model.py, feature_extraction.py, image_preprocessing.py, evaluation.py), `models/face/{face_config.json, face_templates.npy, model_metadata.json}`. Templates are generated by running the notebook (they are in `.gitignore`; share them privately or re-generate).
* Install: `pip install -r requirements.txt` (DeepFace + tf-keras). First run downloads FaceNet/RetinaFace weights (internet needed once); the model is loaded lazily and cached.
* If templates or DeepFace are missing, `verify_face` returns `verified=False, status="model_unavailable"` – i.e. it **fails closed**.
* Merge dependencies into the team `requirements.txt`; do not overwrite it.
